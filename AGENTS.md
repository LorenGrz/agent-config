# agent-config

You've just opened **agent-config**: a portable agent config + skill library. One repo
configures every coding AI a user runs (Claude Code, Codex CLI, OpenCode, plus Cursor and
Antigravity via rulesync) through one tool-neutral layer, `~/.agents/`. See `README.md` for
the full picture; this file is the map for an agent working *in this repo*, not the config it
ships (that's `config/AGENTS.md`, personal content in `config/profiles/<name>.md`).

## If the user asks to install or set up this repo

Use the `agent-config-setup` skill (`skills/meta/agent-config-setup/SKILL.md`) if it's
available; otherwise follow the same steps by hand:

1. Read this repo's `README.md` "Install" section.
2. Run `./install.sh --dry-run` and show the user the plan before touching anything real.
3. Ask the user for their profile name. If `config/profiles/<name>.md` doesn't exist yet,
   offer to create it from `config/profiles/_template.md`.
4. Run `./install.sh --profile <name>` only after the user confirms the dry-run plan.
5. Verify as the skill describes (`~/.agents/` populated, each tool's links resolve).

Never hand-edit `~/.agents/`, `~/.claude/`, `~/.codex/` or `~/.config/opencode/` files that
`install.sh` generated or linked — edit the repo and re-run `install.sh`. It backs up
anything it doesn't own (`.bak.<timestamp>`) before writing.

## Adding or editing a skill

1. Create or edit `skills/<category>/<skill>/SKILL.md` (categories: `aws`, `development`,
   `devops`, `meta`, `productivity`, `quality`, `security`). Frontmatter: `name` (must match
   the folder) and a `description` that states when to use it. Stick to portable fields so
   every tool can load it.
2. Run `./install.sh` to refresh `~/.agents/skills`.
3. Commit with a Conventional Commit subject (`feat:`, `fix:`, `docs:`, `refactor:`, ...).

## Repo conventions

- Commits follow [Conventional Commits](https://www.conventionalcommits.org/). Default
  branch: `master`.
- Structural/trade-off decisions about this hub go in `docs/decisions/` as ADRs (copy the
  newest one's shape).
- No tool-specific file is a source: tool config is either a symlink into `~/.agents/` or
  generated by `install.sh` (ADR 0006). Claude-only pieces live in `config/CLAUDE.md`,
  `config/agents/` and `config/settings.base.json`.
- Personal content (names, paths, learning stage, GitHub owner) belongs in
  `config/profiles/<name>.md`, never in `config/AGENTS.md` or `config/CLAUDE.md`.
- Per-repo scaffolding (for repos *other than this one*) is `skills/devops/project-init`.
